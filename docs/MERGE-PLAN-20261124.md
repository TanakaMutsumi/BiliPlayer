# 合并计划：并入打包版（2026-11-22）的功能

> 目标：两条开发线的功能全部保留在一个代码库里，以源码仓库为主线。  
> 背景：源码仓库（2026-11-24 版）和打包版程序不是新旧关系，而是从 2026-11-07 那版分叉的两条平行线，互不包含。  
> 决定：功能全保留；音效不保留第二套引擎，把打包版的预设转成源码版引擎的参数。

## 1. 两条开发线

打包版目录里没有源码，只有 `resources/app.asar` 的三份快照。解包后做成了三个参照提交：

| 参照分支 | 来源 | 说明 |
|---|---|---|
| `reference/packaged-1107` | `app.asar.orig.bak` | 两条线的共同祖先 |

| 只在打包版 | 只在源码版 |

## 2. 原则

- **功能全保留。** 同一个功能两边各写了一份的，只留一份实现：以源码版的实现为底座，把打包版独有的行为补进去。
- **音效只留源码版引擎。** 两套音效链不能同时处理同一段音频。打包版 46 个预设转成源码版引擎的参数。
- **局域网的配对码校验排在所有路由之前**，包括源码版新增的 `/api/ai/*`（存有 API Key）。
- **不带入 asar 里的遗留文件**：`data/`、`$null`、`.zcode/`、`_g1.js`。

## 4. 对照与验证

- `git diff reference/packaged-1122 -- <路径>`：看某个文件相对打包版少了什么，用来确认没有漏掉功能。
- `npm run test:audio`：6 套离线音频测试，只依赖 Node 内置模块。
- `node --check <文件>`：语法检查。
- `node server.js` 后逐个请求路由：见第 5 节的坑。

## 5. 已知的坑

- **换行符**：仓库工作区是 CRLF，asar 里是 LF。做三方合并前先把两边统一成 LF，否则整篇都是冲突。
- **三方合并的基线**：`netease.js` 在 11-07 还不存在，要用 `reference/packaged-1114` 当基线；其余文件用 `reference/packaged-1107`。
- **合并不报冲突不等于对**：打包版所有调音量的代码都要补 `AudioFX.setVolume()`，否则音效链音量不同步。
- **桌面歌词关闭**：两边修法不同，保留源码版的鼠标穿透热区。
- **`data-action="fx-open"`**：两边都用了这个名字，指各自己的音效面板，只留源码版的。
- **音效预设转换**：均衡曲线要拟合，不能照抄数值。误差数据见第 6 节。

## 6. 音效预设转换的验证数据

离线按频响拟合的结果（RMS 误差，不是试听结果）：

| 做法 | 平均误差 | 误差不到 1 dB 的预设 | 最差 |
|---|---|---|---|
| 数值直接照抄 | 1.80 dB | 16 / 47 | 电话音 6.3 dB |
| 曲线拟合，引擎不动 | 0.63 dB | 37 / 47 | 电话音 3.5 dB |
| 曲线拟合，加频段 Q 值选项 | 0.45 dB | 44 / 47 | 电话音 1.55 dB |

要让转换忠实，源码版引擎需要两个附加选项，只对转换来的预设生效：

1. **动态压缩**：30 个预设用到，源码版没有同类效果。
2. **预设可指定频段 Q 值**：源码版均衡器增益越大峰越窄，打包版的峰很宽。

放宽带段限幅没有用（±6 放到 ±12，平均误差 0.627 → 0.621 dB），瓶颈在 Q 值。

混响和 3D 环绕两边实现原理不同，只能近似；每个预设的响度对齐值要在应用里实测。

## 7. 阶段记录

**阶段 1 后端并入**

- 做法三方合并 6 个文件，新增 `src/qqmusic.js`（打包版原样）。
- 验证：在临时端口启动服务，逐个请求打包线和源码线的路由，全部有响应；压缩、ETag 协商、`.mjs` 类型正常。
- 核对：打包线新增的 648 行逐行检查，没有带进来的只有下面三处，都是有意的。
  - `/api/img` 用源码版的实现（它有重定向处理和容量上限），补上了 QQ 图片域名和对应的 Referer。
  - 网易云取链用源码版的实现。打包版的“旧接口回退”源码版本来就当主路径用，还多了音质档位链和缓存。
  - `netease.js` 里打包版重复声明的 `recommend_songs` 依赖只留一份。
- 顺带修了打包版的一个缺陷：媒体流请求中断时并发计数会被扣两次，时间长了变负数，局域网并发上限就失效了。现在每个请求只扣一次。
- 桌面歌词关闭通知（`widget-window-closed`）主进程和 preload 已就绪，界面侧的监听在前端并入时接上。

**阶段 2 手机端（静态部分）**

- `public/m/` 12 个文件从参照提交原样检出，APK 和图标与打包版逐字节一致。
- 验证：`/m/`、脚本、样式、`manifest.webmanifest`、APK 都能正确提供，类型正确。
- 手机端依赖的后端路由在阶段 1 已全部就绪。桌面端的「连接手机」面板在前端并入时做。
- APK 只有编译产物，壳的源码和签名钥匙不在交付物里，无法重新打包；它内置的网页资源是 11-22 的版本，和仓库里的 `public/m/` 一致。
