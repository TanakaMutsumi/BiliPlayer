# 合并计划：并入打包版（2026-11-22）的功能

> 目标：两条开发线的功能全部保留在一个代码库里，以源码仓库为主线。  
> 背景：源码仓库（2026-11-24 版）和打包版程序不是新旧关系，而是从 2026-11-07 那版分叉的两条平行线，互不包含。  
> 决定：功能全保留；音效不保留第二套引擎，把打包版的预设转成源码版引擎的参数。

## 1. 两条开发线

打包版目录里没有源码，只有 `resources/app.asar` 的三份快照。解包后做成了三个参照提交：

| 参照分支 | 来源 | 说明 |
|---|---|---|
| `reference/packaged-1107` | `app.asar.orig.bak` | 两条线的共同祖先 |
| `reference/packaged-1114` | `app.asar.old2.bak` | 中间版本，功能全部包含在 11-22 里 |
| `reference/packaged-1122` | `app.asar` | 合并时的对照来源 |

判定依据：打包线在 11-07 之后新增的 23 条 API 路由，没有一条出现在源码仓库里。

| 只在打包版 | 只在源码版 |
|---|---|
| QQ音乐、局域网模式与手机遥控、手机端 `public/m/` | 多源歌词管线、动态MV、AI 主题 |
| 定时关闭、最近播放、稍后再看、每日推荐、随机漫游 | 音效链 `audiofx.js`、一起听、DASH 1080p |
| 聚合搜索与联想、纯听全屏播放、系统媒体键 | 网易云心动模式与私人 FM、侧栏背景自定义 |
| 封面主题色、深色模式、光效层、音效工作台 | |
| 大歌单分帧渲染、渲染重入保护等稳定性修复 | |

## 2. 原则

- **功能全保留。** 同一个功能两边各写了一份的，只留一份实现：以源码版的实现为底座，把打包版独有的行为补进去。
- **音效只留源码版引擎。** 两套音效链不能同时处理同一段音频。打包版 46 个预设转成源码版引擎的参数。
- **局域网的配对码校验排在所有路由之前**，包括源码版新增的 `/api/ai/*`（存有 API Key）。
- **不带入 asar 里的遗留文件**：`data/`、`$null`、`.zcode/`、`_g1.js`。

## 4. 对照与验证

- `git diff reference/packaged-1122 -- <路径>`：看某个文件相对打包版少了什么，用来确认没有漏掉功能。
- `npm run test:audio`：6 套离线音频测试，只依赖 Node 内置模块。
- `node --check <文件>`：语法检查。
- `node server.js` 后逐个请求路由：见第 5 节的坑。
- 合并用的辅助脚本（三方合并、按规则解冲突、逐行核对、未定义引用检查、页面冒烟测试、截图）放在 `tmp/merge-tools/`（被 git 忽略），每个文件开头有用法说明。其中未定义引用检查需要 `acorn`，页面测试需要 `playwright-core` 和系统里的 Edge，在该目录下 `npm install acorn playwright-core` 即可。

## 5. 已知的坑

- **换行符**：仓库工作区是 CRLF，asar 里是 LF。做三方合并前先把两边统一成 LF，否则整篇都是冲突。
- **三方合并的基线**：`netease.js` 在 11-07 还不存在，要用 `reference/packaged-1114` 当基线；其余文件用 `reference/packaged-1107`。
- **合并不报冲突不等于对**：打包版所有调音量的代码都要补 `AudioFX.setVolume()`，否则音效链音量不同步。
- **自动合并会拼出语法正确的坏代码**：两边改了相邻的行时，git 不报冲突，但结果可能丢了声明或换错了收尾。合并完必须逐块看差异，并真正把页面跑起来。
- **桌面歌词关闭**：两边修法不同，保留源码版的鼠标穿透热区。
- **`data-action="fx-open"`**：两边都用了这个名字，指各自己的音效面板，只留源码版的。
- **音效预设转换**：均衡曲线要拟合，不能照抄数值。误差数据见第 6 节。

## 6. 音效预设转换的验证数据

离线按频响拟合的结果（RMS 误差，不是试听结果）：

| 做法 | 平均误差 | 误差不到 1 dB 的预设 | 最差 |
|---|---|---|---|
| 数值直接照抄 | 1.80 dB | 16 / 47 | 电话音 6.3 dB |
| 曲线拟合，引擎不动 | 0.63 dB | 37 / 47 | 电话音 3.5 dB |
| 曲线拟合，加频段 Q 值选项 | 0.45 dB | 44 / 47 | 电话音 1.55 dB |

要让转换忠实，源码版引擎需要两个附加选项，只对转换来的预设生效：

1. **动态压缩**：30 个预设用到，源码版没有同类效果。
2. **预设可指定频段 Q 值**：源码版均衡器增益越大峰越窄，打包版的峰很宽。

放宽带段限幅没有用（±6 放到 ±12，平均误差 0.627 → 0.621 dB），瓶颈在 Q 值。

混响和 3D 环绕两边实现原理不同，只能近似；每个预设的响度对齐值要在应用里实测。

## 7. 阶段记录

**阶段 1 后端并入**

- 做法三方合并 6 个文件，新增 `src/qqmusic.js`（打包版原样）。
- 验证：在临时端口启动服务，逐个请求打包线和源码线的路由，全部有响应；压缩、ETag 协商、`.mjs` 类型正常。
- 核对：打包线新增的 648 行逐行检查，没有带进来的只有下面三处，都是有意的。
  - `/api/img` 用源码版的实现（它有重定向处理和容量上限），补上了 QQ 图片域名和对应的 Referer。
  - 网易云取链用源码版的实现。打包版的“旧接口回退”源码版本来就当主路径用，还多了音质档位链和缓存。
  - `netease.js` 里打包版重复声明的 `recommend_songs` 依赖只留一份。
- 顺带修了打包版的一个缺陷：媒体流请求中断时并发计数会被扣两次，时间长了变负数，局域网并发上限就失效了。现在每个请求只扣一次。
- 桌面歌词关闭通知（`widget-window-closed`）主进程和 preload 已就绪，界面侧的监听在前端并入时接上。

**阶段 2 手机端（静态部分）**

- `public/m/` 12 个文件从参照提交原样检出，APK 和图标与打包版逐字节一致。
- 验证：`/m/`、脚本、样式、`manifest.webmanifest`、APK 都能正确提供，类型正确。
- 手机端依赖的后端路由在阶段 1 已全部就绪。桌面端的「连接手机」面板在前端并入时做。
- APK 只有编译产物，壳的源码和签名钥匙不在交付物里，无法重新打包；它内置的网页资源是 11-22 的版本，和仓库里的 `public/m/` 一致。

**阶段 3 前端并入**

做法：21 处（app.js）、10 处（player.js）等冲突按第 2 节的原则解决，然后手工修补自动合并拼错的部位。

带进来的打包版功能：QQ音乐界面与播放分支、听歌时长上报、连接手机面板、定时关闭、最近播放、稍后再看、每日推荐、随机漫游、搜索排序/多源/联想、纯听全屏播放、系统媒体键、封面主题色、光效层、深色模式、窗口标题跟随播放、音量滚轮、切歌串行化、大歌单分帧渲染、渲染重入保护等。

与打包版不同的地方（都是有意为之）：

| 打包版的做法 | 合并版 | 原因 |
|---|---|---|
| 自己的音效引擎和“音效工作台”面板 | 用源码版引擎和面板，预设另行转换（阶段 4） | 两套音效链不能同时处理同一段音频 |
| 单槽预解析缓存 `window.__preMedia` | 用源码版的多槽预取；QQ 直链单独缓存 150 秒 | 源码版的实现更完整 |
| 切歌循环里逐首重试、25 秒超时 | 用源码版的失败处理（连败上限后停止） | 同一功能只留一份实现 |
| `step()` 里的“对象身份兜底”判定 | 只用判定键（已含 QQ 曲目 id） | 加了 QQ id 后它要解决的前提已不存在 |
| “播放速度”菜单 | 不带 | 打包版里就没有定义它调用的 `showSheet`，是个点不动的入口；倍速用源码版音效面板里的 |
| 桌面歌词关闭通知 | 用源码版的鼠标穿透方案，补上主窗口广播关闭指令的处理 | 两边修法不同 |
| 桌面歌词页、样式表 | 保留源码版页面结构 | — |

自动合并拼错、已手工修正的部位（**这类错误语法正确、引用也都在，只有跑起来才会发现**）：

- `player.js` 的切歌函数：结尾被换成了打包版的 `S.index = start`，而 `start` 未定义，源码版的“设置索引 → 加载播放”两行丢了。结果是手动切歌每次都抛异常。
- `player.js`：`_lastGoodTrack` 没有声明、`qqScrobFlush` 没有定义，都是随冲突块一起丢掉的。
- `app.js`：错误处理里 `failStopped` 被置位却不再复位；加载失败提示里用了回滚之后的歌名。
- `desk-lyrics.html`：并入的一行引用了页面上不存在的 `KIND` 和 `closeSelf`，会让桌面歌词收到任何消息就抛异常。
- `style.css`：打包版自己的样式表里有两段属性写在了选择器外面，被浏览器丢弃（视频容器的基础布局属性、全屏音量条的宽度）。按原意归位。

顺带修了打包版的几个问题：每日推荐页的面包屑显示成“我的收藏”；播放页内嵌的播放按钮在合并后与底部播放栏重复出现，改为“播放栏展开时不显示”。

并入 `public/vendor/qrcode.js`（MIT，打包版带着）：两个版本的页面都加载它，但源码包里没有这个文件，源码版一直是 404。

验证：

- 静态检查：按作用域解析所有脚本，没有合并引入的未定义引用。
- 页面冒烟测试（无头 Edge，未登录）：切视图、开六个弹窗、切主题、手机遥控指令、切歌，0 个未捕获异常；合并前的源码版在同一测试里也是 0 个。
- 带真实歌曲的截图流程：网易云匿名播放成功，歌词加载 30 行，纯听全屏可用，0 个未捕获异常。
- 逐行核对：打包线新增的行、源码版原有的行，没带进来或不见了的都逐条确认过是有意的。

没有验证到的（需要登录、真机或 Electron 窗口）：

- QQ音乐登录后的播放和歌单导入。只走到了未登录的报错路径。
- 局域网模式实际开启和手机遥控。开启会绑定所有网卡并触发防火墙提示，测试里没有开；只验证了面板渲染、二维码生成和指令执行函数。
- Electron 专属路径：桌面歌词窗口、迷你播放器窗口、QQ 一键登录窗口、系统媒体键。
